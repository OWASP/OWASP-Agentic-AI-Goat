# ARIA and NOVA explicit snapshot import

`db/postgres/import-workshop-snapshot.js` exports `validateSnapshot(snapshot)` and `importWorkshopSnapshot(migrationPool,snapshot,{apply:false})`. The default validates native constraints inside a transaction/savepoint and rolls back all inserted rows. It takes exclusive table locks for a stable empty-destination check. `apply:true` commits only after every row succeeds, restarts identity sequences transactionally and records seed version 1 so normal startup cannot replenish or overwrite the imported dataset. A direct snapshot call records explicit `direct_snapshot` metadata with `naiveTimestamps: "UTC"`; it does not invent an archive review. It never connects to a source database.

The envelope is exactly `{version:1,family:'aria'|'nova',tables:{tableName:[row]}}`. Every supported table must appear, even empty; every row must have exactly all catalog columns. `catalogs` exports the exact columns. ARIA includes products, orders, receipts, cart and chat_history. NOVA includes papers, authors, reading_lists, chat_history, nosql_injection_solution_visibility and nosql_injection_solutions. seed_state is internal destination metadata, not a source table. Unknown tables/columns, tagged objects, blobs and unsupported scalar types are rejected, never discarded.

Initialize the dedicated empty database with `migrate(migrationPool, familyMigrationDirectory)` only, then import before running normal seed initialization. The caller must supply the dedicated migration role; no identity/platform data belongs in this snapshot. The destination must be empty across all family tables including seed_state. The adapter does not merge or truncate.

Raw JSON columns remain exact strings, including malformed JSON. Owner keys remain exact text; IDs remain positive PostgreSQL integer IDs. Timestamp strings are interpreted by PostgreSQL with UTC as the explicit session timezone; timezone-free legacy timestamps therefore mean UTC. PostgreSQL's timestamp representation preserves the instant to microsecond precision rather than original formatting.

Export normalization is separate and explicit. Legacy NOVA papers lack the new access_level column: an exporter mapping must add `public` (and record that mapping) or provide an explicitly reviewed classification; the importer does not silently infer it. Export archives may contain more tables or tagged types than this logical adapter accepts. Keep that complete archive and create a separately documented logical snapshot. Duplicate cart owner/product rows or orphaned receipts/reading lists that legacy SQLite permitted violate native constraints and cause whole-import rollback; there is no silent deduplication or orphan deletion.

## Export archive CLI

`node db/postgres/import-workshop-archive.js --archive /private/export --family aria --review /private/aria-review.json` verifies a completed `dvaia-sqlite-archive-v1` archive and performs the default database dry run. NOVA uses `--family nova`. Add `--apply` only for the explicit commit. The default environment variable is `SQL_WORKSHOP_MIGRATION_DATABASE_URL` or `NOSQL_WORKSHOP_MIGRATION_DATABASE_URL`; `--database-env NAME` selects an explicit alternative migration connection. The review envelope is exact: `{family,naiveTimestamps,review,ownerBinding,opaqueOwnerResolutions}`. Its nested review binds the archive digest and retained-source disposition; `naiveTimestamps` is `reject` or explicit `UTC`. The CLI validates this envelope before opening identity or destination pools.

The reader validates every archived schema/table file's SHA-256 and byte count, declared row/column counts, and safe single-component regular filenames without following symlinks. Descriptor reads compare file identity, size, and timestamps before and after a bounded read. Manifests are limited to 4 MiB, schemas to 8 MiB each, table payloads to 128 MiB each, and all files read for one archive to 512 MiB. Declared oversized payloads reject before opening or allocating their contents; growth during a read rejects rather than expanding the allocation. Any INCOMPLETE marker or incomplete manifest rejects import. It maps only sql_workshop.db or nosql_workshop.db; other archived sources stay untouched and appear in the mapping report. Extra selected-family tables/columns reject import.

Tagged integers become numbers only when losslessly representable for native numeric columns. Integer owner keys become exact decimal strings, counted explicitly in the normalization report; large keys are not rounded. Text and JSON text remain exact. Blobs and unsupported tagged values reject import. Legacy NOVA's missing access_level becomes public with the number of changed rows reported. Counts and normalization metadata are printed, never row contents or connection credentials. Immutable `import_batches.review_metadata` stores the archive-review hash, timestamp policy, normalization counters, retained-source report and exact opaque-owner resolutions. It is bounded to 64 KiB. Direct snapshot imports use the explicit `direct_snapshot`/UTC record with a null review hash. The CLI never opens a source SQLite database.
