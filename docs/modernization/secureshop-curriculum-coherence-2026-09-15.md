# SecureShop curriculum coherence audit

Date: 2026-09-15  
Scope: the ten `secureshop_agent_security` objectives in six exercise groups

This is a source audit of the current catalog defaults, application workflows, effect evidence, and Judge rubrics. It does not change objective IDs, visibility, instructor-edited content, UI, or intentional vulnerability sinks. No model, browser, service, or database was run for this audit.

The mounted r8 acceptance established current startup, authentication, six-panel rendering, first-help parity, reset, and sibling behavior. It did **not** open or compare the hint and solution content for all ten objectives. The connected tests cited below establish the mechanics they exercise; they are not a claim that r8 browser-tested every default document.

## Cross-cutting recommendation

The ten IDs still cover six distinct mechanisms. Keep all IDs for compatibility, with two explicit curriculum qualifications:

1. `ss_cross_persona_effect` and `ss_acl_advisory_effect` are currently co-awarded from the same advisory read. Reframe them as two observations of one event until a future design gives them independent student evidence.
2. `ss_loop_observation` can share a moderation run with the two review-injection objectives, but it remains useful as a benign orientation prerequisite. Present it first and avoid implying that injected content is required to observe a decision loop.

Default-content repairs should flow through `server/config/secureshopCurriculum.js` and its provenance-aware seed path. The current seed imports these defaults for `secureshop_agent_security`; reconciliation preserves fields already recognized as custom or diverged from the last managed default. A future content migration must therefore update managed defaults without overwriting instructor edits.

Recommended repair order:

1. Correct the rug-pull baseline-invocation sequence before instructors expose that help.
2. Correct stored-browser instructions and its actor-model qualification language.
3. Remove the bound-workflow contradiction in the merchant Reviews disclosure while preserving the truthful legacy/unbound simulation notice.
4. Distinguish the two co-awarded persona objectives and tighten the enforced objective to “no disclosure.”
5. Add persona, page, and exact-control prerequisites to the remaining help and solution documents.

After any default-content change, verify all ten API documents and all ten rendered hint/solution modals against a disposable current-source installation. That is separate from r8's successful first-help and baseline rendering coverage.
