## Source gap closed

The authenticated Supply Chain route previously reduced a platform request to
`user.id`. The graph called the sandbox transport without the durable platform
session, PostgreSQL generation, run identity, or effect ledger. The runner did
execute transform JavaScript inside its ephemeral Bubblewrap filesystem, but
the Judge accepted serializable runner-shaped JSON as `verified_effect`.
Owner reset fenced graph runs, while the sandbox namespace itself remained an
owner-only hash.

The candidate now:

- revalidates the exact bearer against the canonical PostgreSQL identity
  adapter, and binds `user.id` and `identitySession.id` to that result;
- runs chat and reset through the existing buffered `ownerWorkflowRoute`, so a
  disconnected request cannot publish or continue to later mutations;
- derives the runner namespace from owner, platform session, durable
  generation, and run ID, exposing only an opaque digest to the sidecar;
- executes at most one transform through `effectWithReceipt` for a request
  identity;
- uses the reserved, unregistered identity 0053 request journal to claim a
  session-bound key and canonical body fingerprint before model work. An exact
  completed request replays its bounded response; a changed body, old
  generation, different session, or incomplete/uncertain request returns a
  conflict without re-running the model;
- keeps the receipt in a boundary-local `WeakMap`, adopts it across the graph's
  safe DTO clone, and never serializes owner/session/generation receipt data;
- requires that private receipt in `codebot-structured-v6` in addition to the
  existing strict isolation, exit, canary, model-selection, and
  model-observation facts;
- drains owner effects and bumps the owner generation before sandbox cleanup
  and progress reset, with the initiating session revalidated between cleanup
  stages.

The six objective IDs, vulnerable/fixed behavior, UI, fictional
`pkg-parse@1.2.0` teaching sink, synthetic `.env` and SSH fixtures, and
Bubblewrap-only execution rule are unchanged. The legacy `rce_cmd` ID continues
to mean arbitrary JavaScript evaluation; it does not assert an operating-system
command when the runner has not observed one.
