# ARIA/NOVA decision runtime

Live providers now select a structured tool/action in `decide`. LangChain JSON parsing and per-tool Zod contracts validate the selection. LangGraph routes invalid decisions back once for repair, then returns a visible no-action result on exhaustion. Validated tools execute through DynamicStructuredTool. Fixed-mode guardrails remain application policy. Explicit `decisionMode: 'scripted'` and AI_PROVIDER=mock preserve deterministic fixtures and are labeled scripted in traces; they are not live-model evidence.

The default response/tool DTO remains available to service callers. HTTP chat requests add `run: {runId, decisionSource}` for the inspector. `getWorkshopGraphDefinition()` supplies actual node/edge topology. Node timing, model/provider, reported tokens, chosen tool, source, attempts, errors and completion status are available through local bounded `runTraceStore.listRuns/getRun` and the matching PostgreSQL ledger methods. Missing usage is not recorded as zero. No private chain-of-thought, prompt, tool output or credentials are stored in these traces.

PostgreSQL identity migrations 0004 and 0006 provide durable generation/run/effect records and trace events. A dedicated shared pool holds advisory leases; the identity/control pool remains free for authentication, progress and reset invalidation. Lease waits respect abort/deadline. Reset increments durable generation before waiting for active work and clearing stores. A supplied Idempotency-Key claims each effect at most once per generation; an uncertain or previously attempted effect returns an error instead of re-executing. The ledger does not replay a completed HTTP result or resume a graph. Effect tombstones must not be removed as ordinary trace retention.

These records are a run ledger, not a LangGraph state checkpointer. Authoritative conversation messages remain in the workshop store. Cross-database mutations are not atomically committed with identity ledger records; process/network failure between a workshop mutation and its effect acknowledgment remains uncertain and requires reconciliation, never automatic replay. Canonical objective generation must also be compared within its own commit transaction; a runtime check followed by a separate progress write does not establish that guarantee.

Other families currently contain orchestration graphs but still retain rule-based decisions or ordinary model/analysis nodes. They do not yet satisfy the amended requirement that all agent decisions be model-driven. Existing summary prose can hallucinate facts even when tool DTOs are exact; groundedness/judge integration is a separate required gate.

### CTF PostgreSQL store

The staged `WORKSHOP_DATABASE_ENGINE=postgres` selection now routes the CTF namespace to its own database and `ctf` schema. Configure `CTF_DATABASE_URL` for `dvaia_ctf_runtime` and `CTF_MIGRATION_DATABASE_URL` for a separate migration role on that same database. `initializeCtfDb()` applies `db/postgres/workshop-migrations/ctf/0001_schema.sql` and seeds the pure ten-stage catalog from `server/data/ctfDefaults.js`; existing PostgreSQL stage/configuration edits are preserved. Startup readiness is awaited before serving requests. The rollout's default engine remains coordinated with the other stores.

Routes call named asynchronous store operations for participant, stage, hint, event, session, analytics and administration data. Native PostgreSQL SQL uses bound parameters, with no SQLite SQL translation layer. The result graph reads progress through the same store. Supported startup selects the PostgreSQL store only.

CTF database writes share a transaction-scoped advisory lock. Judged completion locks and compares the current progress row identity, stage configuration digest and participant owner before committing the attempt, receipt, progress, score, event and adaptive blocklists together. Reset and stage edits use that same lock. The lock spans database operations only; model inference takes place before acquisition. Receipt tombstones survive reset and prevent an older run from restoring completion. Unavailable judges cannot create winning blocks. Hint purchases compare progress identity and the prior hint count to reject reset/concurrent-purchase races. The conservative database-wide write lock favors correctness at current CTF scale and is a throughput limit, not a per-user parallel write claim.

`server/database/postgres/ctfImport.js` exposes an explicit migration seam: `importCtfSnapshot(migrationPool, snapshot)` imports only into an empty schema, before default seeding. It preserves IDs, UTC timestamps and judgment tombstones and advances identity sequences. It never replaces an initialized target or runs automatically at startup. Import requires an operator-supplied complete snapshot and migration connection; no working database has been imported during development.

The disposable PostgreSQL test covers seed parity, the real result graph DTO, concurrent duplicate winners, restart/reset and stage-edit fencing, no-credit unavailability, transaction cancellation, administration reads, import rejection/roundtrip and a concurrent reset after commit. It is guarded by `PG_TEST_DISPOSABLE=yes` and dedicated `PG_CTF_TEST_RUNTIME_URL` / `PG_CTF_TEST_MIGRATION_URL`. Local tests use no real guardian or judge calls.
